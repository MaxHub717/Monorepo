ADM-011 TO ADM

ADM-011 — Fixture Generation Engine

## Objective

Implement the backend fixture-generation engine that converts a locked division roster into competition fixtures.

## Scope

Support:

* Single round robin
* Double round robin
* Configurable participant count
* Division-specific fixture generation
* Deterministic fixture generation
* Round assignment
* Fixture numbering/order
* Initial fixture status of `SCHEDULED`
* Season/division/participant relationships

Fixture generation must only be available when:

* Season is `ROSTER_LOCKED`
* Division is active
* Division has sufficient eligible participants

## Requirements

1. Generate fixtures from the authoritative locked participant roster.
2. Support single and double round robin.
3. Prevent duplicate participant pairings.
4. Maintain deterministic generation.
5. Persist generated fixtures transactionally.
6. Make generation idempotent.
7. Running generation twice must not create duplicate fixtures.
8. Return useful blocker/error messages when prerequisites are not satisfied.

## API

Implement or update:

* Fixture controller
* Fixture service
* Fixture generation service
* Fixture DTOs
* Persistence layer

## Frontend

Expose fixture generation from the season workspace.

Display:

* competition format
* participant count
* expected fixture count
* current fixture count
* generation status
* blockers/warnings

## Acceptance Criteria

* [ ] Locked roster can generate fixtures.
* [ ] Registration-open season cannot generate fixtures.
* [ ] Insufficient participants are rejected.
* [ ] Single round robin works.
* [ ] Double round robin works.
* [ ] Duplicate generation is prevented.
* [ ] Fixtures are correctly associated with season and division.
* [ ] Fixture generation is transactional.
* [ ] Backend tests pass.
* [ ] Frontend build succeeds.

## Dependencies

* ADM-010 — Roster Review and Lock Workflow

# ADM-012 — Scheduling Density & Competition Configuration

## Objective

Implement configurable competition-density controls so registration volume does not automatically become uncontrolled fixture volume.

## Problem

The platform must support large registration pools without assuming every registered participant enters the same competition division.

The flow must remain:

```text
Registrations
→ Eligible Participants
→ Division Capacity
→ Competition Participants
→ Fixtures
```

## Requirements

Support configuration for:

* Single round robin
* Double round robin
* Division capacity
* Competition participant count
* Scheduling period
* Match frequency
* Match windows
* Concurrent matches where supported

Single round robin must remain supported but must not be treated as the only or mandatory competition model.

The architecture must support large registration pools, including scenarios with hundreds or thousands of registrations, without generating an uncontrolled number of fixtures.

## Acceptance Criteria

* [ ] Registration count is separate from competition participant count.
* [ ] Division capacity controls competition population.
* [ ] Single and double round robin are configurable.
* [ ] Scheduling configuration is persisted.
* [ ] Fixture generation uses competition participants rather than raw registrations.
* [ ] Large registration pools do not cause uncontrolled fixture generation.
* [ ] Validation prevents impossible configurations.
* [ ] Tests cover small and large registration scenarios.

## Dependencies

* ADM-011 — Fixture Generation Engine
